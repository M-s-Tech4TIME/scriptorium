# 2026-10-21 — M3 C4: grimoire tree endpoints — chapters & folios (0023)

Commits: this tranche · Author: alsechemist (with OpenCode) · Milestone M3, tranche C4

## What changed

The book's ordered tree is now a first-class API surface, carrying the
owner's rulings (decision **0023**: D1=A delete-refusal, D2=A owner-only
mutations) and the chapter/folio vocabulary (0022):

- **Router `routers/nodes.py`** under `/api/v1/grimoires/{grimoire_id}`:
  - `GET /tree` — any member; nested `{grimoire_id, nodes:[…]}` with
    `children` arrays (siblings ordered by `position`, `id` tiebreak).
  - `POST /nodes` — owner; optional `parent_id` (root set when nil);
    per-sibling-set slug collision → `409` (DB partial indexes from 0001
    enforce ROOT and child sets alike), position auto = max+1.
  - `PATCH /nodes/{id}` — owner; title/slug renames (0021: sibling-set
    scope, `null` → `422`), `parent_id`-presence re-parent (same Grimoire
    only → `404`; `null` → return to root) with an **ancestor-walk cycle
    guard → `409`**, and 1-based **insert-displacement reuse**
    (Q-M3-4=A: whole sibling set re-indexed in one transaction).
  - `DELETE /nodes/{id}` — owner; **refused `409` while the node holds
    sub-nodes or a folio document** (D1=A; documents pre-date C5, checked
    via `documents.node_id`); refusal writes no audit row; emptied → `204`.
  - Access: viewer/editor members can read the tree; mutations → `403`
    under role, `404` for outsiders; tree assembly + membership reuse the
    M1 helpers.
- **`main.py`**: tree router mounted.
- **Audit actions:** `node_created|patched|moved|deleted` (move = re-parent),
  keyed to the grimoire row.
- **Micro-default (recorded in 0023):** kinds do not restrict nesting —
  the owner's goal is full Sphinx/RTD flexibility (documents are legal
  toctree parents). Strict fold/file-only nesting would be a 2-line veto.
- **Docs:** api.md "Tree — Chapters & Folios" section + audit footer; 0023
  record; data-model "kind chapter|folio" line already from 0022.
