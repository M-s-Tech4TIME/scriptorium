# Technology — Sphinx 9.1.0 + docutils 0.22.4 + MyST-Parser 5.1.0

- Versions (locked): Sphinx 9.1.0 (2025-12-31), docutils 0.22.4 (0.23 gated —
  MyST 5.x upper-bounds docutils; verify in CI before bump, decision 0003),
  MyST-Parser 5.1.0 (2026-05-13, needs Sphinx ≥8<10, markdown-it-py ~4.2).
- Why: documentation engine core; RST default + MyST opt-in per project (§5).
- Used: isolated build venv only (never app deps, Rule 5.4); `backend/app/sphinx/`;
  generated-only `conf.py`, allowlisted extensions (threat model).
- **Staging contract (M4-C2, 0026):** `app/sphinx/sourcegen.py` plans the
  site — per-book directories (docname `book/<…path>/<leaf>`, leaf `index`
  mangled to `index-p`), folio bodies exported **directly from the stored
  canonical TipTap** (the `source_text` cache is never trusted for
  builds), chapters/folio-parents → `toctree` containers, one `conf.py`
  per Athenaeum (MyST/`extensions=["myst_parser"]` only when some book is
  `myst`; master docs are always RST toctree pages). Build sources are
  deterministic (`plan_site` → identical bytes for identical input) and
  fail loud (`StagingError` → build failed, never corrected-guess
  output). **The theme is Scriptorium's own, named `scriptorium` —
  decision 0027:** built from the ground up (no Sphinx builtin /
  third-party template inheritance, `theme.conf` has no parent;
  furo/rtd/alabaster-as-final rejected), while the Sphinx **engine** is
  fully inherited/utilized — builder, environment, toctree/prev-next/
  genindex, `searchindex.js` client search, Pygments. The engine's
  client JS (`searchtools.js`, `doctools.js`, `sphinx_highlight.js`)
  is **vendored at build time** from the installed pinned Sphinx into
  each workspace (never committed, never fetched) — plus the two static
  templates `documentation_options.js.jinja` / `language_data.js.jinja`,
  which with a parentless theme only reach the artifact when vendored
  (the builder then renders them from its own global context;
  `language_data.js`, stemmer JS, `searchindex.js`, `pygments.css`
  remain engine-emitted); the search consumer is first-party (0032):
  `searchindex.js` + `language_data.js` are still engine-emitted and
  bump together with the engine, while `searchtools.js` stays vendored
  but unloaded.
  Implementation template surface: `layout.html`, `page.html`,
  `search.html`, `genindex.html` + one stylesheet
  (`backend/app/sphinx/theme/scriptorium/`); brand injection /
  custom-CSS hooks / dark-mode policy are serving-phase (0026 mandate
  2). **Design baseline (M4-C3.5, decision 0028):** tokens come from the
  owner's approved external consult (dark-forest chrome + cream paper,
  serif body stack, 740px column, 268px sidebar, 56px topbar, every
  value a `--sd-*` custom property); icons are an inline Tabler SVG
  sprite (16 icons, MIT pinned + attribution; zero CDN); callouts use
  11 per-type anchors via `--sd-adm-<type>-{rule,bg,ink}` (uniform
  `--sd-page-ink` body); syntax colors come from a custom Pygments
  `Style` subclass wired via `pygments_style`; the only first-party JS
  is the disclosed copy support script (`scriptorium.js`, 0027 JS
  clause amended); zero asset-injecting extensions in v1; WCAG AA pairs
  are test-pinned (Rule 2). Edge rulings
  E1–E3: empty Athenaeum → 422; empty book → skip + log note; one build
  per Athenaeum at a time (409, enforced in C3). **C3 round-trip
  refinements:** every staged toctree entry is an absolute `</docname>`;
  every referenced page carries its node/book title as a generated top
  section (toctree titles come from the target's own titles); `.md`
  pages emit the MyST fenced `{toctree}` (masters stay RST); the save
  path itself exports sources, so staged builds are exporter-clean by
  construction. **Theme code shipped (M4-C3.5):** the theme package
  (`theme.conf` `inherit = none` — Sphinx 9.1 requires the explicit
  setting; `layout.html` with inline sprite + CSS-only drawer,
  `page.html`, `search.html`, `genindex.html`, `static/scriptorium.css`,
  `static/scriptorium.js`, `style.py`) is staged by the runner
  (`_materialize`) into each workspace beside `conf.py`
  (`html_theme_path=["theme"]`, `pygments_style="scriptorium_style.ScriptoriumStyle"`
  — dotted module resolution, workspace-root style module); the sidebar
  tree rides blanket-page context via `html_context{'sidebar_categories'}`
  (Sphinx validates dict-typed `html_context`) generated by `sourcegen`
  from one page traversal, with first-seen category labels and the
  unlabeled bucket last; the offline-but-real test executes a full
  sandboxed `-W` build with the test interpreter as build python and
  asserts the artifact physiology (exact `_static` inventory incl.
  the two `.jinja`-rendered scripts, byte-identical vendoring, the
  then-current search DOM contract — superseded by 0032 — role="main",
  custom-style spans).
  **0029 preview-feedback pass:** header anchors are the Tabler link
  glyph at every heading level; the one first-party script carries four
  disclosed responsibilities (code-block chrome — language badge read
  from the outer `highlight-<lang>` wrapper, no-language/`default` shows
  `Code` (0034), + always-visible copy; search-result decoration —
  grimoire chip from the
  `#sd-map` island plus the heading chain extracted from the
  artifact's own pages, same-origin, no network; toc scrollspy);
  footer bar removed — Index centered under the sidebar search form,
  per-page credit block ("© Copyright by <librarian display name>.
  Last updated on <build date>." / "Compiled by Scriptorium." from
  `html_last_updated_fmt`); reading layout wide-left with the sticky
  `{{ toc }}` On-This-Page rail; pager = ruled green
  Previous/Next on `--sd-accent-strong`.
  **0031 second-feedback pass (amends 0029):** reading width FLUID (no
  column cap); the sidebar tree is the only hierarchy location — staged
  grimoire/chapter toctrees go `:hidden:` (engine-required,
  rendering-empty; master docs render no list), the site index keeps
  its visible toctree, and grimoire rows in the panel point at the
  FIRST content-bearing folio (`_first_reading_docname` in tree order;
  `"container": True` rows never mark current) — chapters render their
  own body pages (chapters are folios; hierarchy is panel placement).
  The panel sticks with the article (sticky/100dvh/internal scroll)
  and collapses behind one top-bar toggle (two `layout-sidebar`
  Tabler glyphs, persisted `localStorage`). 0034 follow-up: an inline
  `<head>` script applies the persisted collapsed state before first
  paint, so pager navigation never flashes the panel expanded; the body
  script then swaps in the normal `.sd-panel-off` class.
  **Search (0032, superseding 0031 mechanics and 0028's search DOM
  contract):** one first-party core serves the dialog and the full
  `search.html`. The engine-emitted `searchindex.js` is only the
  candidate pre-filter; `language_data.js` supplies stopwords + the
  English stemmer. A query keeps every typed word for display/phrase/
  highlight (stopwords included), scores unique content words
  (stopwords/numbers excluded, stopword-only fallback), takes the
  OR-union of ~10 candidate folios (exact stems, then a guarded prefix
  scan both directions; title terms 3×), fetches those pages
  same-origin (cached), splits them into heading-delimited sections, and
  ranks phrase-first (exact whole sentence +1000; coverage, capped
  frequency, heading hits below); the last token may prefix-match; every
  typed word is highlighted. Results are folio groups with a header
  row, heading-chain/snippet rows, and a grimoire chip; render is
  progressive with a per-surface epoch. The dialog is centred
  (horizontal + vertical) and grows to `min(78dvh, 720px)` with internal
  scroll; Esc/backdrop/Tabler x close; `Ctrl+K` opens. `search.html`
  takes the full surface (`?q=` prefill, history query, no-JS notice)
  and no longer loads `searchtools.js`; the engine's page-level result
  renderer is retired, while `searchtools.js` remains in the vendored
  asset set (0027) unloaded. `file://` previews degrade to
  folio/heading links without snippets (disclosed). A build-time section
  index is the documented scale upgrade, not this tranche.
  **Engine finding (9.1):** `pathto(docname, 1)` = RESOURCE mode
  (the second positional is `resource`, not a relative flag) — all
  sidebar document links must use `pathto(docname)` to get the `.html`
  target; pinned by theme-build tests. The same test now crawls every
  internal `href`/`src` and fails on missing files, directories, or
  paths escaping the artifact (0032 ⑤).
  **Staging finding (0032):** `export_rst`/`export_myst` accept
  `base_level: int = 0`. `sourcegen._page_body` passes `base_level=1`
  because it prepends the page title at level 1, so an authored body may
  start at `h2` (and then use `h3`); standalone exports keep the 0017
  fail-loud default, so a first heading above `h1` still raises.
- **Runner (M4-C3, 0026 P3):** `app/sphinx/runner.py` materializes the
  plan into `/var/lib/scriptorium/builds/{build_id}/` (FHS default;
  `SC_BUILD_ROOT` dev override) and runs `python -m sphinx -W -b html .
  _build/html` — `-W` is the `ok` gate. Child env is a strict whitelist
  (`PATH`, `LC_ALL`, `PYTHONHASHSEED=0`, `HOME` inside the workspace;
  `app.sphinx.runner.child_env`); RLIMITs CPU 600 s / AS 1.5 GiB / FSIZE
  512 MiB / core 0 (`SC_SPHINX_*` overrides); wall timeout 900 s.
  Honest limitation (P3 ruled out containers): egress isolation comes
  by construction of the pinned stack, not a kernel namespace.
  Artifact on `ok`: `{SC_ARTIFACT_ROOT}/{athenaeum}/{build_number}/`
  (html/ + build.log); `SC_BUILD_PYTHON` defaults to `sys.executable`
  pre-packaging (isolated build venv required in production, C4).
